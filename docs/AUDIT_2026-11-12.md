# Portol audit — 2026-11-12

Branch `claude/modest-wozniak-kb7qug` (5 commits on top of `main` @ `585c563`).
Nothing here is deployed: production serves `main`, and every server-side fix
below takes effect only after this branch is merged.

**How it was done.** The live app was driven as the dedicated smoke account
(real browser at desktop / tablet / phone sizes, plus the API), holding the
account's gate lock for every write. Two read-only code reviews (server
authorization; dialog/form behaviour) produced leads; each lead was reproduced
or traced before it was fixed. Client fixes were re-verified in a browser by
running this branch's client against the production API. No real user's data
was read or written; two aggregate, content-free SQL counts were run against
production to size one bug.

Status words used below:

- **Fixed + verified** — fixed, has a test that fails on the old code, and was
  observed working in a browser or against the live API.
- **Fixed + tested** — fixed, with a test that fails on the old code; not yet
  observable live because it is server code that is not deployed.
- **Fixed** — fixed and type-checked / covered by an existing suite, no
  dedicated failing-first test.
- **Unresolved** — confirmed, not fixed (reason given).
- **Not tested** — not exercised in this pass.

## 3. Operations

- **CI on `main` has not run its type check, tests or build since two
  advisories landed.** `npm audit` was the first step of the only job and
  fails on `zod` (< 4.6.6) and `katex` (via `mermaid`); pushes have been going
  out with `SKIP_AUDIT=1`. The audit is now its own job, so an advisory is
  still loud but no longer switches the other gates off
  (`tests/ops-guards.test.ts`). **Fixed** (takes effect on merge).
- **The advisories themselves are unresolved, deliberately.** Both need a major
  upgrade. I tried it: `zod` 4 + `mermaid` 12 clears the audit and 6,694 of
  6,696 tests pass — but the two failures expose a behaviour change that would
  bite every `PATCH` route: under zod 4, `schema.partial()` applies defaults to
  keys the request did not send (renaming a document writes `extractedData: {}`;
  tags and linked profiles would be reset the same way). That is a data-loss
  hazard only two tests happen to catch, so the upgrade needs its own change:
  replace the 12 `insertXSchema.partial().safeParse(req.body)` call sites with
  a helper that keeps only the keys present in the body, then upgrade.
  `zod-validation-error` and `drizzle-zod` are not imported anywhere and can be
  dropped at the same time.
- After merge, tighten contract `DASH-03` (`tests/smoke/contracts/dashboard.test.ts`):
  it expects net worth "≥ 175k", which is why $525k passed. It cannot be
  tightened before the fix is deployed, because the contract suite runs
  against production.

## 4. What was exercised, and what held up

- **Every route at 1440 / 820 / 390 px** (21 routes × 3): no console errors, no
  failed requests, no horizontal overflow. API reads: 100–250 ms warm for every
  list endpoint, bootstrap 630 ms first / 130 ms after (small account).
- **Interaction sweep** — 354 controls on 19 pages at desktop and phone size,
  162 dialogs opened: every dialog closed with Escape and with its X; no dead
  or blocked control; no dialog left the page unclickable. Two flagged items
  were checked by eye and are fine (Calendar Manager scrolls; the filter
  popover fits once its open animation ends).
- **Task workflow in a browser, end to end** (this branch's client, production
  API): Escape discards a draft · double-clicked Save stores one task ·
  survives refresh · clearing the date persists · appears on the dashboard ·
  delete asks first, then removes it. Screenshots in `docs/audit-2026-11-12/`.
- **AI chat on production** (each stored record read back, then cleaned up):
  - "I ran three miles, drank 40 ounces of water, weighed 176 pounds, and slept
    seven hours." → four entries, three new trackers, the existing weight
    tracker reused, no duplicates, correct owner. The run entry also stores
    estimated steps / duration / calories — this is the app's estimation
    engine, and the values are marked as estimates.
  - "Actually I weighed 174, not 176." → the same entry corrected in place.
  - "Remind me about Bob's birthday every September 30 for ten years." → one
    yearly task, first due 2027-09-30, ending 2036-09-30 (ten occurrences).
    The reply ("Added task: Bob's Birthday") does not mention the recurrence.
  - "I spent $42.50 on groceries at Trader Joe's today." → one expense, right
    category, vendor, local date and owner.
  - "I pay $60 for internet every month on the 5th." (a $75 internet bill
    exists) → asked whether to update or add; saved nothing.
  - "Delete it." → asked what to delete; deleted nothing.
- Local suite: **6,803 tests, 412 files, all passing** (was 6,598). Contract
  suite against production: 105 / 105 on both pushes.

## 5. Unresolved product issues (need your decision)

1. **Rewards "Record Redemption" stores points as dollars** — 25,000 points
   becomes a $25,000 expense in spending totals — and then never appears in
   its own list, because the server rewrites the category to `general` and the
   list filters on the category. Warranty claims have the same list problem.
   Needs a place to store non-money records; I did not half-fix it.
2. **Net-worth "this month" after deleting and re-adding an asset** — the
   30-day baseline adds items entered after the stored snapshot on top of a
   snapshot that may already include a deleted copy, so the change can read
   "▼ 50%". Needs per-item history or a different baseline rule.
3. **Failed saves close the dialog first** (tasks, expenses, incomes, tracker
   entries): an intentional "snappy" pattern, but on failure the typed input is
   gone and only a toast remains. Worth revisiting for the long forms.
4. An event can be saved with an end time before its start time.
5. "My dashboard" changes the profile scope for the pages you visit next
   (Bills showed "Everyone", then Tasks showed "Smoke Self" after passing
   through the dashboard). Rule 3 says a control that changes scope must say
   so; a mode switch on arrival is close to the line.
