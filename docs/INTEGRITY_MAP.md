# Integrity map

Generated by `npx tsx scripts/gen-integrity-map.ts` — do not edit by hand.
The model is `tests/integrity/model.ts`; the doors (routes, chat tools, screens) are read from the code.

Two parts. **The dependency map** says, for each kind of record, where it is stored, every door that
changes it, every figure computed from it (and the one module that computes it), and what else must
change when it changes. **The coverage matrix** says, for each data type × operation × door, what
evidence there is that the door works — and it separates a test that *names* a door from a scenario that
*verifies its consequences*.

## Summary

- 25 data types, 10 operations, 3 doors (the app's screens, the API, AI Chat).
- 122 data type × operation rows have at least one door.
- API and AI Chat: 203 doors. **92** are verified by an integrity scenario (the action, the stored row and the dependent figures); **106** more are named by an existing test (evidence, not proof — see docs/WORKFLOW_MATRIX.md); **5** have no test at all.
- Screens: 97 operations are offered by a screen; **4** are driven by an integrity browser scenario (desktop mouse and phone touch). The rest are covered per screen by the live browser checks listed in docs/WORKFLOW_MATRIX.md, not by a database-verified scenario.
- 39 integrity scenarios; 5 drive a browser, 4 drive AI Chat.

## Operations

- **create** — add a record
- **edit** — change a stored value
- **delete** — delete (to Trash where the record has one)
- **restore** — bring back from Trash / a kept version
- **archive** — archive, purge or end for good
- **duplicate** — make an independent copy
- **reschedule** — move a date, one occurrence or the series' rule
- **transfer** — change the owner, the parent or a link to another record
- **cancel** — undo, skip, pause, reverse, dismiss
- **complete** — complete, pay, check in, confirm, tick
